# 掲示板

2ch 形式の **1スレッド限定** の掲示板です。Cloudflare Workers と Cloudflare D1 で動作します。管理画面はありません。スレッドの初期化や「あぼーん」などの運用管理は、Cloudflare アカウントで認証した Wrangler から D1 へ SQL を実行して行います（手順は [ADMIN.md](./ADMIN.md)）。投稿データの正本は D1 の `posts` のみです。HTML・JSON はリクエスト時に生成します。dat は、エンコード済みの行を D1 にキャッシュ（`dat_lines`）し、追加・書き換えのあった行だけを再生成します。

外部ツール・AI クライアント向けの JSON API 仕様は [API.md](./API.md) を参照してください。

## 実装済みの範囲

- 扱うスレッドは 1 つだけです。スレッド作成の機能はなく、初期スレッドは運用 SQL で作成します（[ADMIN.md](./ADMIN.md) の「初期スレッドの作成」）
- 3 種類のインターフェースが、同じ D1 の投稿データを参照します
  - **HTML**（UTF-8）：通常ブラウザ向け。`read.cgi` 形式の URL でスレッド閲覧と投稿ができます。範囲指定や最新 50 件などの表示形式に対応します
  - **dat / raw / subject.txt**（Shift_JIS）：専用ブラウザ向け。`/<板名>/dat/<キー>.dat` の直接取得と、`read.cgi` 経由の raw 取得に対応します。スレッド一覧の subject.txt は `/<板名>/subject.txt` で、スレッドが存在する場合のみ1行で返します（存在しない場合は他のインターフェースと同じく 404 です）
  - **JSON API**（UTF-8）：`/api/v1`。読み取りは認証なし、投稿だけ Bearer トークンが必要です
- 板名は `simple`、スレッドのキーは固定値です（`src/config.js`）。URL は `/test/read.cgi/simple/1795000000/` の形になります
- 投稿は `bbs.cgi` 互換のフォームから行います。名前を省略すると「名無しさん」になります
- 投稿者 ID は 8 文字で、送信元の IP と JST の日付から、`ID_SEED` を鍵とした HMAC で生成します。IP アドレス自体は保存しません
- 投稿の制限：名前 64 文字、メール欄 64 文字、本文 4,096 文字・100 行・1 行 1,024 文字まで。レス数の上限は 5,000 件です
- 連続投稿規制：同じ ID で直近 60 秒に 5 件以上投稿すると拒否されます
- 「あぼーん」は物理削除ではなく、名前・日付・本文などを `あぼーん` に書き換える運用です。番号に欠番を作らないためです（手順は [ADMIN.md](./ADMIN.md)）

## ローカルで試す

Node.js と npm が必要です。先に下の「Cloudflare へデプロイ」の手順で設定ファイルを作り、D1 を作成してください。ローカル実行にはローカル用の D1 を使います。

開発用の secret は `.dev.vars`（`.gitignore` 済み）に書きます。`ID_SEED` がないと投稿が 500 で拒否されるため、任意の長い文字列を設定してください。

```sh
npm install
npm run db:apply:local
npm run dev
```

Wrangler が表示する URL をブラウザーで開きます。初期スレッドはまだ存在しないため、閲覧は「そんな板orスレッドないです。」になります。ローカル用の D1 に対して [ADMIN.md](./ADMIN.md) の「初期スレッドの作成」の SQL を `--local` で実行すると、スレッドが表示されます。

テストは `npm test` で実行できます。一時ディレクトリ内のローカル D1 を使い、HTML・dat・JSON API・投稿・あぼーん用 SQL などを確認します。設定済みのリモート DB には接続しません。

## Cloudflare へデプロイ

リポジトリのルートで実行します。設定ファイルは `wrangler.example.jsonc` をコピーして作ります。`wrangler.jsonc` は各自の環境固有の設定なので、`.gitignore` で除外しています。

```sh
npm install
cp wrangler.example.jsonc wrangler.jsonc
npx wrangler login
npx wrangler d1 create simple-2ch-db
```

出力された `database_id` を、`wrangler.jsonc` の `d1_databases` に書いてください（`binding` は `DB`、コードがこの名前を使います）。その後、マイグレーションの適用、secret の設定、デプロイを行います。

```sh
npm run db:apply:remote
npx wrangler secret put ID_SEED          # ID の種。長いランダムな文字列
npx wrangler secret put API_POST_TOKEN   # JSON API の投稿用トークン（API を使うときだけ）
npx wrangler deploy
```

Worker 名は `simple-2ch` で、デプロイ後の URL は `https://simple-2ch.<アカウントのサブドメイン>.workers.dev/` になります。デプロイ後に、[ADMIN.md](./ADMIN.md) の「初期スレッドの作成」の SQL を `--remote` で実行して初期スレッドを作成してください。

更新時も、**先にマイグレーションを適用してから**デプロイしてください。

- `ID_SEED` が未設定だと、投稿（HTML・JSON）は 500 で拒否されます。閲覧は使えます
- `ID_SEED` を変えると、以降の投稿の ID が変わります。過去の投稿の ID は保存済みの文字列のままです
- `API_POST_TOKEN` が未設定だと、JSON API の投稿系は 503 `API_DISABLED` になります。読み取りは使えます
- レス数の上限などの定数は `src/config.js` にあります。変更したら再デプロイします。スレッドのキーを変えると URL が変わり、専用ブラウザでは別のスレッドとして扱われます

## 運用

管理画面と管理用エンドポイントはありません。初期スレッドの作成、あぼーん、状況の確認、バックアップと復旧は、すべて [ADMIN.md](./ADMIN.md) の SQL 手順で行います。

本プロジェクトでは、既存の 2ch 形式掲示板ソフトウェアのソースコード（内部の関数構成、変数名、処理手順など）は参考にしていません。参考にしたのは、外部から観測できる仕様、すなわち見た目と入出力（HTML・dat の書式、URL、パラメータ、応答、ヘッダー、境界条件）だけです。内部の設計と実装は、それらの観測可能な仕様を入力として独自に行いました。

## 未実装・運用上の制約

- 複数スレッド、スレッドの作成・削除の機能はありません。扱うスレッドは常に 1 つです
- 利用者認証と通報機能はありません。通常ブラウザの投稿に認証はなく、荒らし対策はフォームの検証と連続投稿規制のみです
- 投稿の物理削除はしません。あぼーんは値の書き換えであり、元の内容は残りません
- あぼーんは、取得済みのクライアントには反映されません（差分取得は番号だけで行うため）。また、dat の直接取得（Range）では、あぼーんによって行のバイト数が変わると、専用ブラウザが全体を取り直す場合があります
- 連続投稿規制は ID 単位で数えます。ID は JST の日付を含むため、日付をまたぐ 60 秒間では規制が効きません
- レス数が上限（既定 5,000 件）に達すると投稿は拒否され、それ以上書き込めません
